# همراه‌یاب — قرارداد اولیه API

**وضعیت:** قرارداد طراحی؛ هنوز API عملیاتی یا سرور مستقر نشده است.

تمام مسیرها زیر پیشوند `/v1` و روی HTTPS هستند. شناسه‌ها تصادفی و غیرقابل حدس‌اند. زمان‌ها Unix epoch بر حسب میلی‌ثانیه هستند. پاسخ خطا قالب ثابت دارد:

```json
{ "error": { "code": "forbidden", "message": "درخواست مجاز نیست", "requestId": "..." } }
```

## احراز هویت و دستگاه‌ها

- `POST /v1/auth/challenges`: آغاز چالش ورود با روش هویتی که پس از انتخاب ارائه‌دهنده پیامک/OTP ایران نهایی می‌شود.
- `POST /v1/auth/verify`: اعتبارسنجی کد یک‌بارمصرف؛ ایجاد نشست کوتاه‌مدت/قابل تمدید.
- `POST /v1/devices`: ثبت نصب جدید با شناسه تصادفی تولیدشده در برنامه؛ نام دستگاه و پلتفرم.
- `DELETE /v1/devices/{deviceId}/session`: لغو نشست همین دستگاه.
- `DELETE /v1/devices/{deviceId}`: غیرفعال‌سازی دستگاه تحت مالکیت حساب.

توکن‌ها فقط در حافظه امن/Android Keystore-backed storage نگهداری می‌شوند؛ سرور فقط hash توکن را ذخیره می‌کند. توکن ثابت داخل APK ممنوع است.

## دعوت و اتصال

- `POST /v1/invitations`: ساخت دعوت کوتاه‌عمر با کد تصادفی یک‌بارمصرف.
- `POST /v1/invitations/accept`: پذیرش دعوت توسط حساب دیگر.
- `POST /v1/invitations/decline`: رد دعوت.
- `DELETE /v1/connections/{connectionId}`: قطع ارتباط.

پذیرش دعوت فقط اتصال حساب‌ها را ایجاد می‌کند و به‌تنهایی اجازه مشاهده یا درخواست موقعیت نمی‌دهد.

## رضایت و درخواست موقعیت

- `PUT /v1/connections/{connectionId}/consents`: ایجاد یا تغییر دامنه رضایت توسط صاحب داده.
- `DELETE /v1/consents/{consentId}`: لغو فوری رضایت.
- `POST /v1/location-requests`: ایجاد درخواست با دستگاه هدف و انقضای کوتاه.
- `GET /v1/location-requests/inbox`: دریافت درخواست‌های منتظر پاسخ توسط صاحب دستگاه.
- `POST /v1/location-requests/{requestId}/respond`: تأیید یا رد آشکار درخواست روی دستگاه هدف.
- `POST /v1/location-requests/{requestId}/location`: ارسال fix فقط پس از تأیید معتبر، با مجوز Android و از طریق HTTPS.
- `GET /v1/connections/{connectionId}/last-location`: دریافت آخرین fix فقط با رضایت فعال `view_last_location`.

## قواعد امنیتی الزام‌آور

1. هویت actor فقط از نشست معتبر سمت سرور استخراج می‌شود؛ هرگز از `accountId` ارسالی کلاینت اعتماد نمی‌شود.
2. برای هر خواندن/نوشتن موقعیت، سرور بررسی می‌کند که اتصال فعال، consent دقیق و فعال، مالکیت دستگاه و وضعیت درخواست معتبر باشد.
3. درخواست موقعیت باید pending و منقضی‌نشده باشد؛ عملیات پاسخ/ارسال idempotent و در برابر replay محافظت شود.
4. لغو consent باید قبل از هر پاسخ بعدی مؤثر باشد؛ Push یا پیام صف‌شده مجوز محسوب نمی‌شود.
5. کد دعوت و OTP تصادفی، کوتاه‌عمر، یک‌بارمصرف و rate-limited هستند؛ فقط hash آن‌ها ذخیره می‌شود.
6. مختصات فقط به‌عنوان آخرین موقعیت مجاز نگهداری می‌شود؛ تاریخچه مسیر در MVP نداریم.
7. زمان ثبت، دقت و منبع موقعیت اجباری‌اند. موقعیت قدیمی هرگز live نامیده نمی‌شود.
8. Push فقط شناسه opaque رویداد را حمل می‌کند؛ مختصات و اطلاعات شخصی در payload اعلان ممنوع است.
9. پاسخ‌های خطا، logها و audit eventها نباید مختصات، توکن، OTP یا متن خام درخواست را ثبت کنند.
10. درخواست‌ها دارای محدودیت اندازه، rate limit، زمان انقضا و شناسه idempotency هستند.

## مدل ارسال موقعیت

```json
{
  "requestId": "opaque-id",
  "capturedAtMs": 1795712915000,
  "accuracyMeters": 18.5,
  "source": "fused",
  "latitude": 35.7,
  "longitude": 51.4
}
```

مختصات فقط در endpoint احراز هویت‌شده و پس از بررسی consent/request پذیرفته می‌شود. مثال مختصات بالا داده نمونه است و موقعیت واقعی هیچ کاربری نیست.

## مواردی که پیش از اتصال Android باید نهایی شوند

- روش ورود قابل اتکا در ایران و ارائه‌دهنده OTP/SMS.
- ارائه‌دهنده Push قابل اتکا برای گوشی‌های دارای/فاقد Google Play Services.
- مدت عمر access/refresh token و گردش/ابطال نشست‌ها.
- سیاست حذف حساب و حذف داده مکانی.
- سیاست rate-limit و سقف هزینه.
- نسخه نهایی قرارداد و تست‌های مجوزدهی.
